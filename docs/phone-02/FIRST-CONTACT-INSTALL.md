# AI-PHONE-02 — First Contact Installation Gate

## Purpose
This document is the operator/AI checklist for the first real AI-PHONE-02 contact.

## Package provenance
- Source branch: `mission/phone-02-p238-b-oidc`
- The release workflow builds an **unsigned** MSIX artifact automatically on Windows.
- A signed production package is **not** claimed until the approved signing certificate and verification workflow both succeed.
- Never treat the GitHub source ZIP as an installed Phone-02.

## Windows installation
1. Download the release artifact produced by the **AI-PHONE-02 Release Package** workflow for the exact commit being used.
2. Verify the included provenance and SHA-256 files before installation.
3. Install only on the Windows machine explicitly designated as **AI-PHONE-02**.
4. Do not substitute a CI runner, another PC, or a simulated AppContainer.
5. Launch the packaged application and capture the OS-observed package family, package full name, AppContainer SID, Windows user/session, publisher/signature status, and exact source SHA.
6. Stop if the package is unsigned and the machine does not explicitly allow the approved development/sideload procedure. Do not claim production activation.

## Protected credentials
The Supervisor must keep these credential classes separate:
- OIDC client credential: protected Windows Supervisor store.
- Endpoint operator key: separately provisioned control-plane secret.
- Team Room session bearer: Supervisor memory only after OIDC exchange.
- Endpoint credential: generated by the Team Room endpoint-registration API and retained only by the Supervisor after one-time delivery.

Never put any of these in the AppContainer RPC contract, source code, screenshots, logs, chat messages, or GitHub issues.

## Identity gate
The Supervisor must prove the server-owned `AI_PHONE_ID` matches the locally provisioned Windows installation binding before claiming Phone-02 identity.

## First contact gate
Only after identity, OIDC exchange, endpoint registration/attachment, Team Room join, and heartbeat are real and successful:
1. AI-PHONE-02 sends: "GPT-6, aqui é a AI-PHONE-02. Primeiro contato real iniciado."
2. GPT-6 replies: "AI-PHONE-02, recebi seu contato. Identidade e canal de comunicação confirmados."
3. Record the exact timestamps, server message IDs, source SHA, and runtime evidence.
4. Do not call browser speech synthesis a real AI-to-AI voice channel. Real voice requires a separately verified WebRTC/SIP/telephony path.

## Failure rule
If any gate is missing, report **BLOCKED** with the exact missing gate. Do not manufacture PASS from source code, CI-only tests, UI labels, or a downloaded ZIP.
